## Locked decisions

The two npm packages are byte-identical to the pin's builds and the three wheels to the pin's sources at `825beac28`; the upstream reference commit moves to `9e8a9bac5` (2026-11-02), the commit upstream's Python release tags point at, with no source change to the five packages, the catalogs or the specification since `825beac28`. Main after the release is not the target: its changes are unreleased.

### 2. How the wrapper patches the SDK

Prototype patching. `instrument()` loads `@a2ui/agent` as a peer dependency and replaces the hooked methods on the exported classes' prototypes, keeping the originals for `uninstrument()`. One code path serves both routes, `--import` and the one line, since every hooked name is a method on an exported class and a class is one object per module instance, whether `instrument()` runs before or after the SDK was imported. A second copy of the SDK in the process goes unpatched; that is a note in the README, not a code path.

### 3. The public surface

`A2uiInstrumentation`, a class on `@opentelemetry/instrumentation`'s `InstrumentationBase`, so an agent on its own NodeSDK adds `new A2uiInstrumentation()` to its instrumentations; module-level `instrument({tracerProvider?})` and `uninstrument()` as the one-line form, `instrument()` running the pinned-API check, patching, and starting the provider when the process has none; and the `register` subpath for `node --import a2ui-spectra-instrumentation/register`. `instrument()` is synchronous, loading the SDK through `require()`, with Node 22.12 as the package's floor. A second `instrument()` is one warning line and does nothing; `uninstrument()` restores every original, and a provider the wrapper started stays.

### 4. The hook table

The hooked names, all on the agent SDK, all public, one table: `Parser.parseResponse` on the base, the `parse` event with entry point `parse_response`; `openStream` on the Direct JSON and Express parsers, the `parse` event with entry point `open_stream`, one per stream object, and `feed` and `close` on their two stream classes; `compile` on the two parsers, the `parse` event with entry point `compile` when outermost, and annotating the open event with the block being compiled when inner; `generate` on the two prompt generators, the `prompt_generation` event; `RendererState.checkTopology`, marking a whole-tree check and counting a stream's finished blocks; `RendererState.markChecked`, noting the counts as a stream catches a rejected block's error. The format of a `parse` event is adopted from the parser's class when it is one of the two, else absent, so a third party's own `Parser` subclass used through `parseResponse` still yields a `parse` event with its input and messages and no format. Not hooked: the processor, `StreamedAnswer`, the base `openStream`, `validatePayload`, `RendererState.apply`.

### 5. One event per outermost call

A current-event stack holds the open event, since every hooked call is synchronous; a stream's event is kept on the stream object and entered by each `feed` and `close`. A hooked call made while an event is open opens none, and the inner `compile` annotates the open event with the block it was handed.

### 6. An error's block

For whole-text parsing and an outermost `compile`, the current block is the text the inner `compile` was handed, located in the input from a moving cursor in UTF-16 code units; an error that escapes `checkTopology` carries no block. For a stream, an error belongs to the block it rejected: the text it carries as `rawContent`, located in the input after the last error's block, when it carries one; otherwise the block after those the stream had finished or rejected when the error was raised, among the blocks `unwrap` finds in the input fed so far, a finished block being one `checkTopology` that returned, and the rejected counted at the moment the stream catches the error: each `markChecked` call under a stream event notes the counts then, each error returned in a rejected block's place takes the oldest note, an error thrown takes the last, made as the stream failed, and the notes left at the end are dropped. Either way, the located block is stated whole when the span ends: the block of the stream's whole input, as `unwrap` finds it, that holds the located start. Every stream error is placed exactly, by what the SDK does at the pin, which the capture suite guards.

### 7. A stream's span

A stream's span opens at `openStream` and ends when `close` returns or throws, or when a `feed` throws. Each `feed` is one `a2ui.parse.chunk` span event carrying the UTF-16 length of the input fed so far; `a2ui.parse.input` is the joined chunks, set when the span ends. A `feed` after the stream has ended throws the SDK's plain `Error` through with nothing recorded, and a `close` after the end returns nothing and records nothing. An abandoned stream has its span never ended and never exported.

### 8. What the events carry

`a2ui.parse.messages` is every message of every `a2ui` part the call returned, in order, progressive repeats included, plus the parts a thrown error carries as `partialResults`; an empty list when none. Each error, thrown or returned as an `ErrorPart`, is one `exception` span event with the class name, the message, the stack, the block range by decision 6, and `a2ui.parse.error.details` when the error carries a `details` array whose every item is an object; the status and `error.type` come from the first. `a2ui.parse.streamed`, `a2ui.parse.wrapped` false when the call said `wrapped: false`, `a2ui.parse.entry_point`, and `a2ui.parse.catalogs` from the parser's catalogs, each `{catalogId, protocolVersion}` with the SDK's version string brought to the record's form. `a2ui.sdk.name` is `@a2ui/agent` and `a2ui.sdk.version` is read from the package's `package.json`, found by walking up from the SDK's resolved entry file, because the package's exports map does not expose it. A `prompt_generation` event's `a2ui.prompt.ui_section` is exactly the string `generate` returned, its format from the generator's class, its catalogs from the generator's; a `generate` that throws gives the failed form, status and one `exception` event and no section.

### 9. The pinned-API check and its line

Before patching, `instrument()` and the constructor's `enable()` check that `@a2ui/agent` resolves, that its version is at least 0.1.0, and that every name of decision 4's table is a function on its class's prototype, all standing or falling together, one distribution and one group. A refusal is one WARNING line naming the package and the version found, or that it is not installed, the first missing name, and the pin the wrapper was written against, and nothing is patched. The refusal and a fault inside a hook go through `process.emitWarning`, visible by default; the rest, such as why no provider was started, through OpenTelemetry's `diag` at info and debug, hidden by default.

### 10. The tracer provider

When the process has no provider, the global one being the API's proxy with none registered, and the environment names an endpoint, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` or `OTEL_EXPORTER_OTLP_ENDPOINT`, with the protocol, `OTEL_EXPORTER_OTLP_TRACES_PROTOCOL` or `OTEL_EXPORTER_OTLP_PROTOCOL`, unset or `http/protobuf`, the wrapper registers a `NodeTracerProvider` on the SDK's default resource with a `BatchSpanProcessor` on the OTLP/HTTP trace exporter, which reads the endpoint itself; nothing is added to the resource. Otherwise one `diag` line says what was missing or which protocol was named, no provider is started, and the hooks trace through the API's global tracer, so a provider set later receives the spans. A provider already set is kept, as is one passed to `instrument({tracerProvider})`. The provider the wrapper started is shut down on `beforeExit`, once, which flushes a natural exit, the driver's included; no signal handlers. An agent stopped by a signal keeps only what the processor had already exported, the batch delay being OpenTelemetry's default and tunable through its `OTEL_BSP_*` variables.

Dev dependencies: `@a2ui/agent` 0.1.0 for the tests, and the shared tooling. The instrumentation scope is `a2ui-spectra-instrumentation`, its version the package's.

### 12. The driver

One file, `driver.ts`, in a private workspace package at `conformance/wrapper_driver/typescript/`, built by its own wireit `build` and listed in the root workspaces, the tool's `test` target depending on its build; it depends on the wrapper as `workspace:*` and on `@a2ui/agent` 0.1.0. It behaves as the conformance README and the records fix: the one-line form first; the processor the job describes, `A2uiRequestProcessor` on the job's format factory, a custom catalog loaded from its path and a renderer state bound when the job says; `generate` through `promptSnippet`, `parse_response` and `open_stream` through the processor with `wrapped` and `afterRejectedBlock`, the stream fed each chunk cut at the job's UTF-16 ends and closed unless one threw, `compile` through the processor's parser; a `tool_call` job fails as unknown. The SDK's `A2uiError` passes and the driver exits 0, the provider's shutdown on `beforeExit` flushing the export; anything else exits non-zero with its message on stderr. It prints nothing, carries no trace context, and shares no code with `_dev/tools/wrapper_capture_facts.mjs`. The basic catalogs are the driver's own copies of the pin's two files, under its package, v0.9's serving v0.9.1 too, loaded through `FileSystemCatalogProvider` with the job's catalog id: the driver's stand-in for what the Python SDK has built in.

## Invariants

- The wrapper never changes what the SDK does: it returns what the SDK returns and throws what it throws. A failure inside the wrapper never reaches the agent; it is one warning line.
- A record states what happened: the wrapper reports the input, the messages, the format and the errors, and no ranges; the retry, the component ranges, the model call a parse read and the parse a component came from are computed when shown.
